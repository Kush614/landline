## 0. Ground rules

1. Ship the thin vertical slice first (Phase 1) before touching any sponsor that isn't Stripe/Linq/Render/Terac. A working ugly loop beats a beautiful broken one.
2. Never invent API shapes. For every sponsor, `WebFetch` their docs first (links in §5), read them, then implement. If a doc is unreachable, ask the human for the doc URL or an API key; do not guess.
3. Every secret goes in `.env` and is read via `process.env`. Commit `.env.example` only.
4. Every external call gets a 20s timeout, one retry, and a fallback so a single sponsor outage never kills a customer flow. (`src/http.ts` — `req()` and `softly()`.)
5. Log every agent decision to `logs/decisions.jsonl` (timestamp, agent, input summary, output summary). This is demo material and Band/judging evidence.
6. Time-box: if any single integration passes 45 minutes without a working call, stub it behind a feature flag and move on. Report back with what's blocked.
7. Keep `STATUS.md` updated after every phase.

## 1. Product scope

### 1.1 In scope (MUST)
- Customer texts a Linq iMessage number with a brief in natural language.
- Agent pipeline produces **3 variants** of a single-page static site (mobile-first, one hero, one features/benefits block, one CTA, optional pricing block, optional embed slot).
- Variants are shown to real humans via **Terac**; winner is picked from human preference data.
- Winner is **QA'd by Replay**; bugs are auto-fixed and re-QA'd until clean (max 3 loops).
- Winner is **deployed on Render**.
- Customer receives an **iMessage App card** with live preview thumbnail + status (Building → Testing → Human-testing → Live) + **Pay** button (Linq Agent Pay → Apple Pay → our Stripe).
- Payment through the ONE Stripe Payment Link submitted to organizers ("Customer chooses price").
- Tiers: $9 page · $19 page + QA certificate + subdomain · $29/mo "site care" (revisions by text).
- Revisions: customer replies "make it darker" → agent resumes the customer's Superserve VM, edits, re-QAs, redeploys, replies.
- Agents coordinate in **Band** with real dependencies (see §3.3).
- Copy generated by an **open-weight model on Pioneer**; PII scrubbed with **GLiNER2-PII** before anything is stored or shown to Terac panelists.
- Public **revenue dashboard** (built in Lovable) showing $ earned, sites shipped, Terac studies run, QA passes.

### 1.2 Out of scope (do NOT build)
- Multi-page sites, CMS, auth, databases for the customer's site, custom domains, e-commerce carts, blogs.
- Our own auth/accounts. The phone number is the account.
- Refunds/disputes flows. Compliance agent prevents bad orders instead.
- Anything requiring app store review.

### 1.3 Nice-to-have (SKIP IF LATE, in this order of dropping)
1. Whop $29/mo subscription + template pack
2. Egoist Machines brand context pull
3. Solari competitor screenshots
4. sandbox0 isolation of customer embed code
5. Pioneer fine-tune on Terac winners
6. Dodo Payments for non-US buyers

## 2. Architecture

```
iMessage (Linq) ──webhook──▶ API (Node/TS, Render Web Service)
                                  │
                                  ▼
                        Band room "landline-hq"
        ┌───────────┬────────────┼────────────┬────────────┐
       CEO       Designer     Copywriter      QA        Sales/Compliance
        │            │            │            │             │
        │      Superserve VM   Pioneer      Replay        Stripe link
        │      (build/edit)  (open model)  (QA loop)    + veto rules
        │            │
        │            ▼
        │       Terac study (3 variants → human winner)
        │            │
        ▼            ▼
   Render Workflow: build → qa → terac → deploy → notify
                                  │
                                  ▼
                       hosted site per customer
                                  │
                                  ▼
                 Linq iMessage App card + Agent Pay → Stripe
```

**Stack:** Node 20+ / TypeScript, Fastify, single-file inlined-CSS generated sites, SQLite (better-sqlite3) for job state, Render for hosting, no ORM.

**Data model (SQLite)** — see `src/db.ts`
- `orders(id, phone, chat_id, brief, brief_scrubbed, tier, complexity, status, slug, deploy_url, superserve_vm_id, band_thread_id, compliance, stripe_paid, amount_cents, …)`
- `variants(id, order_id, idx, label, html_path, preview_url, terac_score, replay_status)`
- `studies(id, order_id, terac_study_id, question, results_json, winner_variant_id, model_pick_variant_id)`
- `votes(id, order_id, variant_idx, clearest_idx, trust, would_pay, comment, voter)`
- `events(id, order_id, agent, type, payload_json, ts)`

## 3. Agents

### 3.1 CEO (orchestrator)
Owns order state. Reads incoming brief, opens a Band thread per order, assigns tasks, decides tier upsell, decides when to ship. Can only mark `LIVE` after QA is clean **and** a winner exists **and** Compliance has not vetoed. (`canGoLive()` in `src/pipeline/run.ts`.)

### 3.2 Roles
| Agent | Input | Output | Sponsor |
|---|---|---|---|
| Designer | brief | complexity estimate (S/M/L) + 3 layout specs | Superserve VM builds |
| Copywriter | brief + layout specs | headline/sub/CTA × 3 | Pioneer open model, GLiNER2-PII scrub |
| QA | deploy preview URL | Replay report → fix list → CLEAN/FAIL | Replay |
| Sales | complexity estimate | price tier + payment link msg | Stripe link |
| Compliance | brief + copy | APPROVE / VETO(reason) | rules + model |
| E-com Specialist | only spawned if brief mentions selling products | pricing block spec | runtime add |

### 3.3 Band dependencies (MUST — Band judges check that removing Band breaks it)
1. **Sales blocks on Designer:** Sales cannot post a price until Designer's complexity estimate lands in the thread. An actual wait on a Band message, not a local variable.
2. **Compliance can veto:** any deploy step reads the latest Compliance verdict; VETO halts and CEO texts a polite decline. Test brief: "supplement that cures anxiety".
3. **Runtime specialist:** if CEO classifies the brief as e-commerce, it adds the E-com Specialist to the thread at runtime; Designer's layout changes based on that agent's post.
4. **QA changes Copywriter:** if Replay flags a broken CTA/link, QA posts it and Copywriter must re-emit CTA copy.

All four write a `bandDependency` field into `decisions.jsonl`. Kill-switch: `BAND_ENABLED=false` halts the company.

## 4. Pipeline — one order end to end

1. `intake` — Linq webhook → create order → typing indicator → CEO opens Band thread → PII scrub (GLiNER2-PII) → Compliance pre-check.
2. `design_copy` — Designer + Copywriter → 3 variant specs.
3. `build` — create/resume Superserve VM for this order → render 3 HTML files into the customer's workspace.
4. `human_test` — Terac study over the 3 variants → poll → pick winner → store scores. **Fallback if results aren't back in time:** ship the model's pick, keep polling, and if humans disagree, redeploy the human winner and text "we upgraded your page — 63% of testers preferred this one."
5. `qa` — publish winner → Replay run → parse → auto-fix loop (max 3) → CLEAN.
6. `deploy` — publish final URL.
7. `notify` — Linq message/card: status LIVE, URL, price, Pay link. Post summary to Band.
8. `revise` — on a new text from a known phone: resume that order's VM → apply edit → re-run 5–7.

Every step is idempotent (re-run safe) and updates `orders.status`.

## 5. Sponsors — verified API facts

Everything below was confirmed by fetching the sponsor's own docs. Where a doc was silent, that's called out as unverified — **do not guess, ask**.

### 5.1 Terac (Host — REQUIRED for eligibility)
- Base URL `https://terac.com/api/external/v2`, auth `Authorization: Bearer <apiKey>`.
- Flow: `POST /projects` → `POST /opportunities` (draft) → `POST /opportunities/{id}/launch` → `GET /opportunities/{id}/submissions`.
- `createOpportunity` requires: `title`, `project_id`, `num_participants` (1–1000), `business_type` (`b2c`|`b2b`), at least one `tasks[]` entry with `sequence`/`task_type`/`review_type`/`task_url`/`duration_minutes`, and either `filters` or `unrestricted_audience: true`.
- **Unverified:** allowed values for `task_type` and `review_type`. Env-overridable, soft-failed.
- Credits: https://terac.com/r/rGi7O0EfkRbzmiElg8kRjES5W2JrKNYc — target **General Population**.
- **Study question set (§5.1 of the original brief), implemented on our own page at `/study/:orderId`:**
  1. Which of these three would you most likely click "Get started" on?
  2. Which headline tells you most clearly what this is?
  3. Rate trust 1–5.
  4. What's confusing or missing? (free text, optional)
  5. Would you pay $9 for a page like the winner? ← feeds the pricing meta-study
- **Evidence to save for judges:** model-pick vs human-pick per order, % preference, redeploys triggered by humans, pricing study result. In `studies.jsonl` + dashboard.

### 5.2 Stripe (REQUIRED for both $2,500 prizes)
- Human does this: personal Stripe account → Payment Link, "LANDLINE Payment", **Customer chooses price** → restricted key `hackathon-readonly` with **Balance: Read, Charges: Read, everything else None** → submit team name + link + `rk_` key to organizers.
- Use only that one link all day; never share `sk_`.
- Dashboard reads `GET /v1/charges?limit=100` with the `rk_` key.
- Env: `STRIPE_PAYMENT_LINK`, `STRIPE_READ_KEY`.

### 5.3 Linq (Best use — $1,500 / $1,000)
- Base `https://api.linqapp.com/api/partner/v3`, auth `Authorization: Bearer $LINQ_API_KEY`. SDK: `@linqapp/sdk`.
- `POST /messages` `{to:[…], message:{parts:[{type:"text",value:"…"}]}}` → `{chat_id, from, service, message}`.
- `POST /chats/{chat_id}/messages` to continue a thread.
- `POST /webhook-subscriptions` `{url, events:["message.received"]}`.
- Webhook signature: headers `webhook-id`, `webhook-timestamp`, `webhook-signature`; HMAC-SHA256 over `"{id}.{timestamp}.{rawBody}"`, base64, constant-time compare, reject if older than 5 min.
- Agent Pay: `POST /v3/payments/handles/{handle}/connect` → `POST …/verify` `{connect_id, code}` → create payment `{handle, amount_cents, currency, description, merchant}` → `GET /v3/payments/{id}/credentials`.
- **Sandbox constraints:** inbound-first (they must text us first); **no links in the first outbound message**; 100 unique conversations; number lives 7 days.
- **Unverified:** typing-indicator endpoint, tapback send/receive, iMessage App card schema. Ask in Discord.
- Signup: https://linqapp.com/hackathon → Sandbox Signup → "Hackathon".

### 5.4 Replay (Best use — $1,000 / $500, +$50 per false-positive report)
- Base `https://loop-qa.replay.io/api/v1`, auth `Authorization: Bearer lqa_…`. OpenAPI at `/api/v1/openapi.json`.
- `POST /projects` `{name, target_url}` → `GET /projects/{id}/status` → `GET /projects/{id}/bugs` → `GET /bugs/{id}` → `PATCH /bugs/{id}` `{status:"fixed"}` (auto-retries the journey).
- Credits: https://qa.replay.io/ → billing → code `HACKATHON`.
- Side quest: log false positives to `logs/replay-false-positives.md` and report them.

### 5.5 Superserve (Best use — $1,000 / $500)
- SDK `@superserve/sdk`, reads `SUPERSERVE_API_KEY` from env.
- `Sandbox.create({name, timeoutSeconds, metadata, envVars, network, previewAccess})`, `Sandbox.connect(id)` (auto-resumes), `sandbox.commands.run()`, `sandbox.files.write/read/list`, `sandbox.pause()`, `sandbox.getPreviewUrl(port)`, `sandbox.publishPreviewPort(port)`, `Sandbox.list()`, `Sandbox.killById(id)`.
- **One persistent VM per order; pause between turns, resume on revision — call this out explicitly in the demo.**
- Docs: https://docs.superserve.ai/sdk-reference/sandbox

### 5.6 Pioneer by Fastino Labs (Best use — $500)
- Base `https://api.pioneer.ai/v1`, auth header `X-API-Key`.
- `POST /v1/chat/completions` (OpenAI-compatible), `POST /inference` (native), `POST /v1/messages` (Anthropic-compatible), `GET /base-models`.
- Decoders: `nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16`, DeepSeek V4 Flash, GLM 5.2.
- **GLiNER2-PII:** model `fastino/gliner2-privacy-filter-PII-multi`, called via `/v1/chat/completions` with `{schema:{entities:[…]}, include_spans:true, include_confidence:true}`. 42 PII types.
- Credits: https://agent.pioneer.ai → Billing → Get Pro → promo `ZeroHumanHack0826`.

### 5.7 Band (Best use — $500)
- Agent API base `https://app.band.ai/api/v1/agent`, auth `X-API-Key` (plus an agent UUID). SDK `@band-ai/sdk`.
- `GET /me`, `GET /peers`, `GET /chats`, `POST /chats/{id}/participants`, `POST /chats/{id}/messages`, `POST /chats/{id}/events`.
- Routing is by `@mention`: agents see only what they're mentioned in. WebSocket subscriptions are required to *receive*; REST is enough to *send*.
- Credits: https://www.band.ai/ → code `HACKBANDAUG26`. Hacker guide: https://www.band.ai/hacker-guide.

### 5.8 Render (Best use — $500/$300/$100; MUST use Render Workflows)
- Workflows SDK: `npm install @renderinc/sdk` (≥0.5.0). `task({name, timeoutSeconds, plan, retry}, async fn)`; tasks call other tasks directly; `render.yaml` service `type: workflow`.
- Trigger: `new Render({token}).workflows.startTask('my-workflow/taskName', [args])` or `runTask(...)` to wait. Observe with `getTaskRun`, `listTaskRuns`, `taskRunEvents`.
- Static sites: `POST /v1/services` `{type:"static_site", name, ownerId, serviceDetails:{buildCommand, publishPath}, repo, branch}` — **requires a git repo**, which is why we serve customer sites from the web service instead (see STATUS.md).
- Credits: https://credits-portal-mmdm.onrender.com/claim/terac-hackathon

### 5.9 Lovable (no prize track)
- Marketing page + live revenue dashboard consuming `GET /api/dashboard`.
- Credits: lovable.dev → Settings → Plans & Credits → code `COMM-THE-4G9T`.

## 7. Acceptance tests

Implemented in `test/smoke.ts` (`npm test`). Runs with zero sponsor keys; tests needing live credentials are reported as SKIP.

1. `POST /webhooks/linq` with a fake brief → order row created, Band thread id set.
2. Builder produces 3 valid HTML files < 60KB each, mobile viewport, lang, no dangling anchors.
3. Terac winner selection; fallback executes when scores are missing; humans override the model pick.
4. QA flags a broken CTA → Copywriter re-emits it → second run is CLEAN.
5. Site published and served; path traversal refused. *(Render static site: manual.)*
6. Tapback parsed. *(App card + Agent Pay: manual.)*
7. Revision reuses the same VM id and redeploys.
8. Band kill-switch: `BAND_ENABLED=false` → Sales never prices, CEO never opens an order.
9. Compliance veto: "supplement that cures anxiety" → VETO → decline sent, no deploy.
